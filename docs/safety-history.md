# 安全历史时间筛选与分页

2026-11-24 增量。复用已有安全事件、授权及关闭原因，不新增表、迁移或后台服务。App 的“安全→安全历史”提供今天、近7个当地自然日、全部历史；围栏/策略修改仍属于独立配置历史，不混入安全事件。

## 读取合同

`GET /api/v1/pets/:id/safety-events`，使用当前用户 Bearer 令牌，按当前家庭成员权限读取指定宠物。viewer 可读；被撤权或跨家庭访问按原宠物授权拒绝，分页游标不授予权限。

| 查询参数 | 规则 |
| --- | --- |
| `from` / `to` | 可选，必须同时提供；ISO 时间必须包含时区，服务端归一为 UTC。按事件 `occurred_at` 的 `[from,to)` 筛选，`from < to`，最长 `31 × 24` 小时。未提供且无带范围游标时保持全部历史，不默认截取24小时 |
| `limit` | 1–200，默认50 |
| `cursor` | 使用响应中的 `next_cursor` 原样续页。客户端不解析或拼装 |

示例：上海时区2026-11-24当天是 `from=2026-11-23T16:00:00.000Z&to=2026-11-24T16:00:00.000Z`。URL中的偏移量 `+08:00` 必须按查询参数编码，建议使用 `URLSearchParams`。

```json
{
  "items": [],
  "next_cursor": null,
  "range": {
    "from": "2026-11-23T16:00:00.000Z",
    "to": "2026-11-24T16:00:00.000Z"
  }
}
```

全部历史的 `range` 为 `{ "from": null, "to": null }`。事件继续返回原有字段、解析后的 `details` 和 `closed_reason`；`next_cursor=null` 表示没有下一页。事件排序固定为 `occurred_at DESC,id DESC`，相同采样时刻以ID排序。

## 固定范围续页

新游标为版本化 base64url 查询位置，包含当前用户、宠物、归一时间范围、排序及末条时间/ID。续页可以只带 `cursor` 和 `limit`，恢复原窗口；也可重复相同的 `from/to`。更换用户、宠物、范围或排序的游标会被拒绝，切换筛选应清空列表和游标后重新查询。游标是查询参数，不是加密数据或授权凭证；每页都在事务中重新检查当前宠物访问权。

新游标按时间/ID续页，末条记录随后被删除时仍能继续。兼容旧客户端传入原始事件UUID，但只允许未筛选的全部历史，且必须找到属于本宠物的锚点；带 `from/to`、不存在或其他宠物的旧锚点拒绝。所有响应的新游标均使用上述版本化格式，旧客户端应原样回传。

分页不是冻结数据库快照。期间插入、修改或移除的数据以每次查询时可见记录为准，重新刷新可读取最新结果。

| 错误 | 说明 |
| --- | --- |
| `400 INVALID_RANGE` | 缺一端、起止相同或反向 |
| `400 RANGE_TOO_LARGE` | 窗口超过31×24小时 |
| `400 INVALID_CURSOR` | 游标损坏、范围/用户/宠物不匹配，或旧UUID不适用于当前请求 |
| `400` 参数校验错误 | 无时区/非法日期、limit越界等，沿用统一参数校验响应 |
| 既有认证/宠物授权错误 | 会话失效、无当前访问权等，不能靠旧游标继续读取 |

## App 的自然日操作

客户端通过现有 `activity/daily` 或 `activity/weekly` 接口取得服务端当地日期和 `period_start/period_end`，再查询安全历史。今天覆盖一个当地自然日；近7天包括今天及之前六个自然日。跨夏令时可能不是24/168小时，不使用手机时钟或固定小时倒推日期。应用筛选后固定本次范围，翻页不随时间滑动；切换日期范围、时区或宠物重新加载。

查看列表和切换筛选不产生安全确认或通知已读。事件详情中的显式确认仅记录人工知晓，不关闭围栏风险，也不代替通知中心本人已读。缺少设备/位置数据不推断“安全”。
