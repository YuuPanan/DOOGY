# App 软件闭环演示

这是用户确认的独立合成环境，用于操作和复读软件流程。普通业务库不会自动导入这些资料；`offline` 表示服务器不调用外部业务服务，手机仍需要连接后端，不是手机断网运行 NestJS。

## 一键体验

1. 在电脑双击根目录 `start-app-demo.bat`。它复用 `start.bat` 的 Node24、依赖同步、最新源码编译和 API/Worker 管理；构建失败立即停止。
2. 每次启动新建 `data/app-demo-<随机编号>/`，保存 SQLite、demo.env 和 demo.json。保留旧演示资料，不读取用户 `.env`，也不使用其业务库或投递凭据。
3. 此显式 App 演示入口监听本机局域网，终端打印手机可达地址候选。手机与电脑需网络可达，App 填写根地址，不附 `/api/v1`；Android 模拟器可填 `http://10.0.2.2:<端口>`。本机回归可直接运行 `node dist/scripts/app-demo.js <端口> --loopback`，不监听局域网。
4. App 登录页展开连接设置 → 填地址 → 检查连接。服务端明确报告合成演示时，才显示“填入合成演示主人账号/只读账号”；填入后点击登录。普通环境不出现这些入口。
5. 可另外注册新账号体验无宠物引导：建立档案 → 保存 → 明确跳过项圈 → 自动进入今天。内测包仍需用户选择真实条款版本时再记录接受事实。
6. 终端按 Enter 或 Ctrl+C，既有管理器关闭本次 API 和 Worker；不会按端口停止其他项目。局域网演示使用公开测试凭据，仅用于受控合成测试，不作为生产服务。

要继续某次演示已保存的数据，关闭原服务后，用该次目录的环境文件启动，**不要再次加 app-demo 参数**：

```bat
start.bat "data\app-demo-该次随机编号\demo.env"
```

这会复用同一 SQLite、端口、账号和已保存记录，不重新种入演示资料。每次双击 `start-app-demo.bat` 则明确创建一套新的演示；已有目录保持不动。普通业务环境继续使用自己的后端地址和 `start.bat`，两类资料不会自动合并。独立SQLite演示无需启动Docker/PostgreSQL。

## 数据与操作

| 数据 | 可验证操作 |
| --- | --- |
| 主人/只读两个身份、两只宠物、合成项圈与遥测 | 切宠、只读限制、围栏/配置历史、策略和走失请求、解绑后从本人设备列表找回并续码绑定 |
| 体重、餐食、目标、身体观察和完整日评估 | 新建/更正/撤回与汇总、Goal/Body同范围草稿、版本冲突、已阅与反馈 |
| 5个课程、1个结构化运动计划、4个提示/指导 | 分类搜索、正文/来源、步骤与本人已学、计划选用草稿/显式保存、课程上下文问题 |
| 一秒合成PCM静音、人工行为、解释及本人会话 | 授权媒体读取/播放、解释与问答由真实 Worker 处理为明确的离线固定演示、本人解释反馈提交和复读 |
| 同意报告不同的联系人、混合结果通知请求 | 显式选择/版本、逐人结果、历史/重试/取消；没有真实外发或自动附位置链接 |

内容标题、正文、适用范围、来源及审阅者均注明合成/软件流程用途，不能当成专业宠物照护审核。媒体 fixture 只声明 synthetic_fixture，不冒充真实上传或解码验收；服务端真实四格式上传另有 [媒体测试](../test/media-upload-e2e.test.ts)。演示种子不自动导入普通库；内容导入入口和既有审核合同保持。

软件验收清单见 [51画板核对表](app-closed-loop.md)，启动和实际验证见 [协作流程](process.md)。未知评分、真实硬件、地图、身份供应商、消息渠道和模型能力继续如实门控，不使用演示数据伪造生产结论。
