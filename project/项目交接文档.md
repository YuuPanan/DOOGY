## 2. 产品与当前边界

- Android 优先，iOS 后续；中国大陆与海外均需支持，通过显式区域和 API 地址选择访问相应环境，不自动跨区复制账号或数据。
- App 采用 React Native + TypeScript + Expo development build；后端沿用 NestJS API 与独立 Worker；兼容 Web 保留。
- 已有账号、家庭、宠物、引导、日常照护、活动/营养、Goal/Body、课程/计划、媒体、行为解释、本人问答、设备/安全、联系人、工单及数据管理软件流程。
- `offline` 指服务器不调用外部业务服务，App 仍需要网络连接后端；当前没有手机离线业务库、离线提交队列或内嵌后端。
- 身体观察 appetite、energy、movement、stool 保存可空原文，暂不评分。未知测量不补零，不生成未确认的健康或饮食结论。
- 外部模型、具体地图/身份/消息供应商和真实硬件尚未完成接入验收。演示解释、问答、通知或设备数据必须保留合成/模拟/未配置标识。

详细状态与开发项见 [需求任务文档](项目需求与开发任务.md)，不能把“页面存在”“接口受理”或“编译成功”当作真实设备执行或生产验收。

## 3. 接手者的第一次运行

以下命令使用 Windows PowerShell，在克隆后的仓库根目录执行。需要 Git、Node.js **24.x** 与 npm；建议沿用锁文件，不在首次接收时升级依赖。

```powershell
git clone https://github.com/YuuPanan/DOOGY.git
cd DOOGY
node --version
npm.cmd --version
npm.cmd ci
.\start-app-demo.bat
```

已经取得源码 ZIP 或本机 `DOOGY_clean` 时，直接在该目录从版本检查、`npm.cmd ci` 开始，无需再次克隆。

该入口新建 `data/app-demo-<随机编号>/`，生成 SQLite、`demo.env` 和 `manifest.json`，然后启动 API、Worker。不读取原业务 `.env`，不要求 Docker。控制台打印当前端口、局域网候选地址和演示账号说明。

在第二个终端启动 App：

```powershell
cd mobile
npm.cmd ci
if (!(Test-Path -LiteralPath '.env')) {
  Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
npm.cmd run check
npm.cmd run android
```

`run android` 需要第 5 节的 Android 工具链和已连接的设备/模拟器；已有开发包时用 `npm.cmd start` 启动 Metro。可用 `npm.cmd run web` 辅助查看界面，Web 预览不能代替原生终端验证。

在 App 登录页展开连接设置，选择 CN/Global，填写**服务根地址，不带 `/api/v1`**，检查连接。后端报告独立合成演示时才出现“填入演示主人/只读账号”，填入后仍需点击登录。普通库不自动创建公开测试账号或课程。

| 使用场景 | 地址与检查 |
| --- | --- |
| 电脑访问自己后端 | `http://127.0.0.1:<控制台端口>` |
| Android 模拟器访问宿主机 | `http://10.0.2.2:<端口>`；此地址不适用于真实手机 |
| 真实手机访问开发电脑 | 手机可达的电脑局域网地址；核对网络、监听地址和防火墙规则 |
| 健康检查 | 服务根地址下 `/api/v1/health`，检查 mode、database、demo |
| 动态接口文档 | 服务根地址下 `/docs` 与 `/openapi.json` |
| 兼容 Web | 服务根地址下 `/app/` |

演示停止：在启动终端按 Enter 或 Ctrl+C，让管理器关闭本次 API/Worker。验证重启持久性时，先停止原服务，再用**同一份**环境文件启动：

```powershell
.\start.bat "data\app-demo-该次随机编号\demo.env"
```

不要再次双击 `start-app-demo.bat` 冒充同库恢复：每次该入口都会创建新的演示库。[演示详情](docs/app-demo.md)。

## 4. 普通环境、数据库和媒体

普通环境首次只在文件不存在时复制模板，并检查值；不得覆盖已有配置：

```powershell
if (!(Test-Path -LiteralPath '.env')) {
  Copy-Item -LiteralPath '.env.example' -Destination '.env'
}
.\start.bat
```

| 配置 | 作用与交接要求 |
| --- | --- |
| `HOST`、`PORT` | 普通模板默认 `127.0.0.1:3000`；真实手机联调须由操作者明确配置可达监听地址；独立 App 演示已处理局域网监听 |
| `DATA_MODE` | 默认 offline；改为 api 不会自动接通模型、短信、供应商云或地图 |
| `DB_DRIVER`、`DB_PATH` | 默认 SQLite 和本地数据库路径；不是手机本地数据库 |
| `DB_DRIVER=postgres`、`DATABASE_URL` | 选择 PostgreSQL；独立于 offline/api，使用自己的 `.env.postgres`，不覆盖 SQLite 配置 |
| `MEDIA_TOOLS_DIRECTORY` | 服务端 ffmpeg、ffprobe 所在目录；默认 `.tools/media/`；二进制需自行准备 |
| `EXPO_PUBLIC_CN_API_URL`、`EXPO_PUBLIC_GLOBAL_API_URL` | `mobile/.env` 或构建终端中的公开根地址，会进入 App，不得放账号或密钥 |
| 管理员、Webhook、投递、备份/保留配置 | 按环境模板及对应合同由授权人员设置，不把家庭 owner 当作平台管理员 |

SQLite 开发不需要 Docker。要使用本地 PostgreSQL/PostGIS，先按 [双库说明](docs/postgres.md) 准备独立配置和 Docker Engine，再执行：

```powershell
if (!(Test-Path -LiteralPath '.env.postgres')) {
  Copy-Item -LiteralPath '.env.postgres.example' -Destination '.env.postgres'
}
npm.cmd run postgres:up
.\start.bat .env.postgres
```

当前 61 张业务表，最新 SQLite `034` / PostgreSQL `023`，迁移由启动准备阶段应用。修改表结构必须提供两套**新增**迁移，不重写已应用文件。SQLite→PG 导入只读源库、目标必须为空，双方没有自动双向同步。[数据流](docs/database-dataflow.md) / [备份恢复](docs/database-operations.md)。

真实上传需要服务器安装 FFmpeg 和 ffprobe。先检查 `/pets/{id}/media/capabilities`（统一加 `/api/v1`）；缺工具时应得到明确未配置能力。首版最大 60 秒、20 MiB，实际校验 WAV PCM、MP3、M4A AAC、MP4 H.264（可带 AAC），保留至主动删除或删除宠物；录音约 59 秒自动停止。解码成功不表示行为识别。[媒体合同](docs/media-upload.md)。

备份、恢复、导入、删除重放涉及真实数据，按模块文档使用独立目标演练；不要复制运行中的单个 SQLite `.db` 当作完整备份，不清空用户数据库，不使用 `docker compose down -v` 排障。

## 5. Android 开发和 APK 交付

准备 JDK **17**、Android SDK **Platform 37**、Build Tools **37.0.0**、Platform Tools 和 Command-line Tools；锁定依赖还使用 NDK **27.1.12297006**、CMake **3.22.1**。`JAVA_HOME` 指向 JDK 根目录，`ANDROID_HOME` 指向 SDK 根目录，使用生成工程的 Gradle wrapper。[工具链详细步骤](mobile/docs/android-toolchain.md)。

在 `mobile` 目录执行，构建根可换成自己项目外的短英文路径：

```powershell
npm.cmd run check
npm.cmd run apk:android -- E:\AndroidDev\b
# 需要模拟器测试 ABI 时，另选 QA 构建
npm.cmd run apk:android:qa -- E:\AndroidDev\b
```

默认 ARM64；QA 为 ARM64+x86_64。脚本复制隔离快照、检查依赖、fresh prebuild、Gradle 构建并生成 `<构建根>/artifacts/dgy-<随机值>/` 下 APK 和 `receipt.json`；失败不交付旧包，不自动安装。两种命令只生成各自请求的包。

当前 App 源码 0.1.4 / Android versionCode 5。preview 包名 `com.doogy.mobile.preview`，采用 debug 测试签名、内嵌 JS、不依赖 Metro。构建脚本不读取/复制 `.env*`；预填公开 API 地址须在构建终端设置或安装后输入。交付含源码输入清单及关联摘要的构建回执，Git来源不可用时明确留空，不能把ZIP推定成某个提交。正式签名、商店上架和生产 HTTPS 配置另行验收，iOS 原生构建需要 macOS/Xcode 与签名。[APK 合同](mobile/docs/android-apk.md)。

交 APK 时同时给出源码提交、版本/code、ABI、SHA-256、独立验签结果、后端根地址及运行要求、已验设备/API和未验项。旧安装包不代表本次接收的源码已重新构建。

## 7. 前后端协作不可破坏的合同

1. 沿用 `ApiClient` / `MobileApi`，保留 Bearer 刷新、请求 ID、错误、幂等键和原生上传适配。服务端成功响应没有统一 `data` 包装，错误按 `code/message/request_id` 处理，字段以 [fb.md](fb.md) 为准。
2. owner、caregiver、viewer 每次读写均由后端复核；viewer 的本人学习、已阅、问答等例外按接口权限处理。本人会话/反馈/进度不得转为全家庭共享。
3. 同一业务意图重试沿用幂等键；版本/attempt 冲突保留草稿并明确重读。计划选用只预填，用户保存才写入。

## 9. 常见阻塞与下一步

| 现象 | 先检查 |
| --- | --- |
| 手机连不上 | 根地址是否多加 `/api/v1`；是否用了仅模拟器可达的 `10.0.2.2`；HOST、端口、局域网与防火墙 |

| 解释、问答、事件一直排队 | Worker 是否与 API 使用同一环境/数据库并正常运行 |
| 无法上传媒体 | capabilities、服务端工具目录、实际编码/时长/采集时间及当前角色；不是只检查扩展名 |
| 构建失败 | Node24、两端依赖、JDK/SDK、构建根路径及实际错误；不跳过检查或拿旧包替代 |
