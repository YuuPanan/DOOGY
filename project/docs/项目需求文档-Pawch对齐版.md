# DOOGY Mobile｜项目需求文档（Pawch 原型对齐版）

版本：1.1 · 核对日期：2026-11-28（北京时间） · 用途：本地开发、测试及交接  
适用工作区：`E:\Doogy_ma\project`。本文件汇总最新需求口径，不覆盖原稿，不改变未确认的 API、数据库或产品规则。DOOGY 是当前工程名称；Pawch 是本次设计稿名称，正式产品名称、包名与发布签名未因本次审阅而变更。

## 1. 项目目标与范围

面向宠物主人和授权家庭成员，围绕当前宠物查看日常状态，记录照护与行为、查看定位安全信息、学习，并在明确选择上下文后进行问答。先交付 Android 可安装、可复测的核心闭环；实际跑通后才做 iOS 适配与独立终端验收。测试包、软件回归、原生验收与生产放行是四种不同的结果，不相互替代。

沿用现有 React Native + Expo + TypeScript、React Navigation、AppContext、ApiClient/MobileApi 和 SecureStore；沿用 NestJS API + 独立 Worker、SQLite 开发及 PostgreSQL/PostGIS 试点路径，不为对齐导航重写客户端或后端。CN/Global 服务区域显式选择，不自动跨区同步。合成演示环境仍需可达后端；普通业务库禁止自动导入样例、假设备或演示内容。E 盘保存项目、工具链、依赖、缓存、临时文件和构建产物；不能可靠重定向的工具先停对应步骤，不迁回、不清理 C 盘。

## 4. 重要分歧与决策边界

1. **Wellbeing 评分**：原型显示活动、睡眠、身体、营养四项各 25%，并有 80/100 样例；不是生产算法。当前遵循原 D06/R05：显示原始事实、观察、来源及覆盖，不上线该总分。需独立确认分项定义、数据覆盖、缺项规则、解释方法和验收样例。
2. **设备与安全**：原型的 150 m、350 m、±12 m、75% 电量及模式频率是样例，不写成产品默认值、效果或 SLA。真实 BLE、独立设备远程链路、位置地图、项圈动作、推送/短信分别以样机、协议、授权、区域和回执验收。
3. **餐食拍照与录像**：列为待产品确认的候选需求，不能引入相机、后台能力、模型调用或上行真实媒体作为对齐动作。现有手填餐食、前台录音及系统导入优先。
4. **课程与 AI**：原型可验证“阅读 → 携带上下文提问”的路径；不证明内容授权、真实回答、诊断或照护正确性。
5. **走失与外发**：保留本地模拟确认和实际的内部安全状态；真实路由、收件方和对外送达未经确认不实现、不自动发送。界面不得把模拟、应用受理或联系草稿描述成已送达。

## 5. 状态、权限与数据

所有写流程必须覆盖载入、空态、无权限、编辑、取消、提交中、成功、失败/可重试和返回重读。按钮在提交中防重复；写入成功而读失败只重试读，不重复写；涉及版本时明确冲突并保留用户草稿。切宠、切家庭、切账号或 API 区域后，旧请求/确认弹窗/媒体引用不可污染当前页面。家庭共享与本人会话、进度、已阅分范围授权；权限以 API/Worker 访问时的检查为准，不靠隐藏按钮。演示、实际设备、用户手填与推导结果分别标明来源，保留时间及缺失状态；删除、撤回和权限变化后旧来源和派生结果不能复活。离线断网不显示已保存，不承诺自动排队，用户可恢复网络后显式重试。
