# 五分钟 MVP 演示

本演示用独立的本地数据展示 DOOGY 的宠物照护与穿戴设备业务流程。账号、宠物、位置、活动、通知和设备回执全部是合成样例；页面仍通过实际业务 API 读写数据，没有连接真实项圈、厂商平台或手机推送。

## 启动

先安装 Node.js 24，双击项目根目录的 [start-demo.bat](../start-demo.bat)。也可在项目根目录的 PowerShell 运行：

```powershell
./start.bat demo
```

`start-demo.bat` 调用已有 `start.bat demo`，先同步依赖、编译最新源码，再创建一个新的 SQLite/offline 演示库，准备样例并启动 API 与 Worker。等待窗口输出 `[DOOGY MVP] 演示入口`，打开该完整地址的 `/app/` 页面。登录页应显示「合成数据演示 · 可直接体验」，点击「主人演示登录」或「只读演示登录」即可进入，无需手输密码、自行注册或预置设备。页面同时显示当前访问地址，方便与终端核对。端口自动选择，不能固定使用普通模式的 3000 端口。

需要手工填写时，使用下表中的公开合成凭据：

| 身份 | 邮箱 | 密码 |
| --- | --- | --- |
| 主人 | `owner@doogy-demo.example.invalid` | `Doogy-MVP-demo-2026!` |
| 只读成员 | `viewer@doogy-demo.example.invalid` | `Doogy-MVP-demo-2026!` |

这些内置账号和预置数据由独立演示创建。普通库中即使手工注册了同名邮箱，也不表示固定演示密码有效或已经生成样例。`start.bat .env demo`、`start.bat .env.postgres demo` 同样进入独立的 SQLite/offline 演示，忽略前面的环境文件；不会切换或覆盖用户原有 `.env`、SQLite 或 PostgreSQL 业务数据。

已经安装项目依赖时，也可使用：

```powershell
npm.cmd run demo:mvp
```

该命令同样先编译，并创建新演示数据。普通 `start.bat` 与 `start.bat .env.postgres` 保持原有数据库和数据模式行为，需使用在对应环境注册的账号；`npm.cmd run demo` 也继续用于原来的命令行演示。

### 无法用演示账号登录时

1. 查看登录页环境提示。显示「当前是普通数据环境」时，当前地址连接的是普通业务库；从项目目录双击 `start-demo.bat`，打开新窗口打印的完整演示地址。
2. 核对页面显示的访问地址与终端地址一致，不沿用旧标签页、收藏中的端口或固定 `3000`。保持本次演示启动窗口运行，按 Enter 会停止服务。
3. 必要时在当前地址把 `/app/` 换成 `/api/v1/health`。演示应为 `demo: true`，并带 `demo_accounts`；普通环境为 `demo: false`，完全省略演示账号字段。`mode: offline` 只表示不访问外部业务服务，两类环境都可以是 offline，不能用它区分演示库。
4. 演示页如果提示重启入口，或仍没有两个快捷登录按钮，重新运行最新的 `start-demo.bat`，打开本次输出的新地址；不要向用户原业务库补种演示账号或重置已有账号密码。

## 按 1→9 展示

1. **点击「主人演示登录」，查看日常概览。** 选择「豆豆（合成演示）」，查看 8.6kg 体重、活动、78% 电量、围栏外状态、开放事件和未读通知。先说明样例来自合成遥测，当前没有真实宠物或项圈数据。另一个「糯米（合成演示）」用于最后的换绑体验。
2. **展示照护记录和资料维护。** 进入「照护记录」，查看体重、喂食、排泄、自定义训练及笔记。修改一条笔记、查看历史，再打开已有的合成图片附件。也可以添加一条新照护或上传本地图片/PDF；宠物栏点击「修改资料」，修改名字或品种后，检查页面是否反映新资料。
3. **展示活动趋势和观察反馈。** 在「活动趋势」查看前七天上报步数、覆盖情况和今日同进度比较。用「查看日期」选择昨天，在「所选日期的活动观察」打开步数变化的「查看证据」，核对覆盖率和基线。主人可选「有用」或「不准确」，填写说明后提交。只读成员可查看证据。今日样例随启动时刻生成，自然日刚开始时可能尚无当日活动样本。
4. **展示足迹与事件追溯。** 点击「足迹与事件」，查看九个合成定位点、局部轨迹示意及事件列表，打开一次离开围栏事件的详情。确认知晓后，开放事件不因此关闭；通知标为已读只影响当前账号。位置范围只筛位置，事件历史独立分页；示意图没有地图底图，不用于导航或精确距离测量。历史明细显示的是采样新鲜度，不能据此推断当前宠物位置或当前绑定可追踪。
5. **展示通知中心。** 点击顶部铃铛，从「未读」中选择一条合成通知查看关联事件，返回后将其标为已读，再切换到「已读」核对。打开提醒偏好，切换并保存一个类别，然后重新打开检查保存结果。合成投递状态展示的是离线模拟结果。[通知中心与提醒偏好](workbench.md#通知中心与提醒偏好)
6. **展示家庭协作与只读身份。** 顶栏点击「家庭」打开「家庭与成员」，查看当前家庭及成员。主人可修改家庭设置、生成邀请、调整照护者/只读角色；邀请码由演示者自行交给受邀用户，系统不发送邮件。退出后点击「只读演示登录」，选择共享的「豆豆」：可以读取照护、活动、位置和事件，不能修改共享家庭的宠物、照护、围栏、设备策略，也不能代替主人确认事件。打开通知中心，核对主人已读的通知在该账号仍为未读，本人也可标记已读和修改提醒偏好。只读账号另有注册时创建的个人家庭，在该个人家庭中仍是 owner。
7. **展示客服工单。** 可先选未绑定设备的「糯米」，从顶部「我的工单」点击「绑定前求助」，提交一条合成文字问题。再选已绑定设备的「豆豆」并使用「提交工单」，体验主动授权诊断及撤销。使用已配置的客服账号处理两类工单，再切回提交者查看回复和状态变化。[客服工单操作](workbench.md#7-提交工单与客服处理)
8. **展示设备操作与走失分享。** 回到主人账号，查看已应用策略与 `simulator` 执行来源。手动开启短时走失模式，再在同一面板点击「位置分享」，选择时限并勾选同意后创建链接。将链接粘贴到同一台电脑的无痕窗口，即可免登录查看合成位置。回到主人页面撤销分享，再刷新接收页，确认链接已失效。开启走失模式后若显示等待回执，说明后续设备回执尚未收到。最后可尝试解绑：保存界面给出的设备 ID、新绑定码和有效期，切换到「糯米」后重新绑定。历史位置、照护和事件继续保留，新绑定的当前状态须等新上报确认。
9. **展示数据自助导出。** 从顶栏「数据导出」查看个人分区和各家庭的角色及分区。点击「生成导出文件」，核对记录数和分区数，再点击「下载 NDJSON」。用文本编辑器打开合成文件，可查看首行清单、照护附件记录和末行完成标记。使用只读演示账号还可核对个人家庭与共享家庭各自的角色和分区。[Web 导出操作](workbench.md#8-自助导出账号与家庭数据)

演示账号默认只有家庭权限。演练客服处理时，可在独立演示库注册专用客服账号，登录后通过 `GET /api/v1/auth/me` 读取该账号 UUID，停止服务，在本次演示的 `demo.env` 增加 `SUPPORT_ADMIN_USER_IDS=<UUID>`，再用下方的继续启动命令恢复同一个演示库。原业务配置继续供普通环境使用。[客服账号配置](../fb.md)

演示默认监听 `127.0.0.1`，创建的链接只在本机可用。给其他设备上的接收者分享时，须使用双方都能访问的服务地址。详情见 [走失位置分享](workbench.md#走失位置分享)。

为了保留完整开场效果，先展示概览、足迹和告警，再执行确认、改角色、走失或解绑。重复操作需要全新开场时，停止本次服务，再次运行 `start.bat demo` 创建新样例。

## 保存、继续与停止

每次启动保存在独立目录：

```text
data/mvp-demo-<随机标识>/
  doogy.db    演示业务数据
  demo.env    继续启动此演示的配置
  demo.json   合成账号与样例标识、创建时刻
```

按终端中的 Enter 或 Ctrl+C 停止本次 API 与 Worker。要保留改过的资料并继续上次演示，用终端打印的实际目录替换下列占位路径：

```powershell
./start.bat data\mvp-demo-<随机标识>\demo.env
```

普通恢复启动不会再次种入样例，因此会保留上次的记录、角色、确认和换绑结果。再次执行 `start.bat demo` 则创建新目录，旧演示资料保留，不会自动清空。

默认演示把设备在线与定位新鲜度阈值设为 30 分钟，并不是持续发送遥测。位置按采样时间自然过期，设备状态也会随后变为离线或未知；长期打开页面时用刷新按钮读取实际状态。要重新展示新鲜位置，可创建新的演示。该行为不代表设备故障，也不能把合成发送状态解释为手机实际送达。

## 展示范围与验收

当前目标是可供实际操作的 Web MVP。SQLite/PostgreSQL 及 offline/API 的正常运行模式继续保留；此专用演示入口始终使用独立 SQLite/offline，便于没有厂商接口或云凭据时展示。

演示没有安卓安装包、真实硬件或厂商接入、手机推送、外部地图，也没有完整的手机断网同步。MVP 是否满足需求，以用户完成上述核心操作后的试用反馈为准；自动化、启动和浏览器的实际验证结果见 [acceptance.md](acceptance.md)，后续进度见 [协作流程](process.md)。
